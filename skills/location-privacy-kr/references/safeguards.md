# 보호조치와 기록 (실태점검 준비)

법 제16조 제1항은 관리적·기술적 보호조치를, 제2항은 확인자료의 자동 기록·보존을 요구한다. 세부 기준은 방송미디어통신위원회 고시 「위치정보의 관리적·기술적 보호조치 기준」을 따른다. 코드로 확인할 수 있는 것과 문서·운영 증빙으로만 확인할 수 있는 것을 나눠 판정한다.

## S1. 확인자료 자동 기록·보존 (형사처벌 조항)

두 종류의 확인자료가 있다. 어느 쪽도 위치정보(좌표) 자체를 담지 않는다.

| 자료 | 정의 | 누가 |
|---|---|---|
| 위치정보 수집사실 확인자료 | 수집요청인, 수집일시, 수집방법에 관한 자료 (법 제2조 제4호) | 위치정보사업자 |
| 위치정보 이용·제공사실 확인자료 | 제공받는 자, 취득경로, 이용·제공일시, 이용·제공방법에 관한 자료 (법 제2조 제5호) | 위치기반서비스사업자 |

통과 기준:
- 위치를 쓰는 서버 경로에서 **자동으로** 기록된다. 수기 대장이나 필요할 때 뽑는 방식은 통과가 아니다.
- 최소 필드(이용·제공사실): 대상(정보주체 식별자), 취득경로(GPS, Wi-Fi, Cell-ID 등), 취급자(서비스 주체), 제공 서비스, 제공받는 자, 이용·제공 일시.
- 보유기간은 6개월 이상으로 두고, 그 근거와 기간을 약관에 적는다.
- 확인자료 열람·고지 요청을 처리한 기록(취급자, 요청자, 목적, 일시)도 남긴다.

코드에서 볼 것: 위치 API 핸들러 안에서 감사 로그를 남기는 코드, 해당 테이블·로그 스트림, 보존 정책(TTL, 로그 보존 일수).

## S2. 위치정보시스템 접근기록

- 위치정보를 다루는 직원이 시스템에 접속해 처리하면 처리일시, 처리내용, 접속기록이 자동으로 기록·보존되어야 하고, 정기적으로 확인·감독해야 한다.
- 관리자 콘솔, DB 직접 접속, 내부 API에서 위치 데이터를 조회하는 경로를 찾는다. 접근 로그가 없으면 "미흡".
- 사업 개시가 1년 미만이면 개시일부터의 기록을 낸다.

## S3. 접근 통제와 인증

- 위치정보시스템 접근 권한을 필요한 사람에게만 주고 변경 이력을 남긴다.
- 인증: 안전한 비밀번호 규칙, 무작위 대입 대응, 기본 계정 제거. 가능하면 OTP·인증서·생체 등 추가 인증.
- 전송 구간 암호화(HTTPS), 저장 시 보호(저장한다면).

## S4. 관리 체계 문서 (코드로는 확인 불가, 증빙 목록으로 안내)

실태점검에서 흔히 요구하는 내부 관리지침 목차:

1. 목적
2. 위치정보의 정의와 적용 범위 (서비스·기술에 맞게)
3. 위치정보보호조직: 조직도, 위치정보관리책임자 지정(임원 또는 고충처리·위치정보 관리 부서의 장), 책임자·취급자의 역할, 취급자 변경 기록
4. 위치정보 취급과 관리: 취급대장 운영, 열람·고지 요구와 불만 대응, 접근사실 자동 기록·보존 장치 운영, 보유와 파기
5. 침해사고 대응: 보고·신속대응 체계, 대응 절차(준비, 탐지, 초기 대응, 대응 전략, 조사, 보고서, 복구·재발 방지)
6. 교육: 목적, 내용(법령, 절차), 연 1회 이상 일정
7. 연 1회 이상 내부 정기 감사
8. 기술적 보호조치: 접근 차단, 암호화 등

## S5. 위치정보를 서버에 저장하지 않는 경우

- 일시적으로 서버에 올렸다가 바로 지워도 위치기반서비스사업이면 의무가 적용된다.
- 서버에 저장하지 않는다는 주장은 확인자료와 자동삭제 소스코드 등으로 증빙한다. 스킬은 해당 코드 위치(파일:줄)를 증빙 후보로 정리해 준다.

## 판정 표기

| 항목 | 코드로 확인 | 증빙 필요 |
|---|---|---|
| S1 자동 기록 | 기록 코드, 테이블, TTL | 실제 6개월 이상 보존 설정 |
| S2 접근기록 | 관리자 경로 로그 코드 | 정기 확인 기록 |
| S3 인증·통제 | 인증 미들웨어, 권한 체크 | 권한 부여 대장 |
| S4 관리 체계 | 해당 없음 | 지침, 조직도, 교육·감사 기록 |
