# 개인정보 처리방침 체크리스트

두 층으로 본다. 1층은 개인정보보호법 제30조와 시행령의 일반 기재사항, 2층은 개인위치정보 처리방침 기재사항(위치정보법 제21조의2)이다. 위치 항목은 별도 문서로 두거나 개인정보 처리방침 안에 통합할 수 있다.

법령과 작성지침은 자주 바뀐다. 점검 날짜를 보고서에 적고, 항목이 애매하면 국가법령정보센터(law.go.kr)의 현행 조문과 개인정보보호위원회의 최신 「개인정보 처리방침 작성지침」을 확인하라고 표시한다. 과태료 금액이나 시행일을 기억에 의존해 단정하지 않는다.

## 1층: 개인정보 처리방침 일반 항목

| # | 항목 | 비고 |
|---|---|---|
| P1 | 처리 목적 | 기능·서비스별로 구체적으로. "등" 남발 금지 |
| P2 | 처리하는 개인정보 항목 | 필수·선택 구분, 자동 수집 항목(기기 식별자, 접속 기록) 포함 |
| P3 | 처리 및 보유 기간 | 법령상 보존 근거가 있으면 법령명과 기간 |
| P4 | 파기 절차 및 방법 | 시점, 방법, 분리 보관 근거 |
| P5 | 제3자 제공 | 받는 자, 목적, 항목, 보유기간. 없으면 없다고 |
| P6 | 처리 위탁 | 수탁자와 업무. 클라우드, 분석, 메시징, 지도 API 포함 여부 |
| P7 | 국외 이전 | 해외 클라우드·SDK로 넘어가면 이전받는 자, 국가, 항목, 시기·방법, 거부 방법 |
| P8 | 정보주체와 법정대리인의 권리·의무와 행사 방법 | 열람, 정정, 삭제, 처리정지, 동의 철회 |
| P9 | 안전성 확보조치 | 관리적·기술적·물리적 조치 |
| P10 | 자동 수집 장치 설치·운영과 거부 | 쿠키, 광고 식별자(ADID, IDFA), SDK |
| P11 | 행태정보 처리 (해당 시) | 수집 항목, 목적, 거부 방법 |
| P12 | 개인정보 보호책임자와 고충처리 부서 | 성명 또는 부서, 연락처 |
| P13 | 열람청구 접수·처리 부서 | |
| P14 | 권익침해 구제 방법 | 분쟁조정위원회, 침해신고센터 등 외부 기관 안내 |
| P15 | 처리방침 변경 | 시행일, 이전 버전 열람 방법 |
| P16 | 해당 시: 가명정보, 자동화된 결정, 전송요구권, 민감정보·고유식별정보 | 서비스에 해당 처리가 있을 때만 |

## 2층: 개인위치정보 처리방침 항목 (위치정보법 제21조의2)

| # | 항목 |
|---|---|
| L1 | 개인위치정보의 처리 목적과 보유기간 |
| L2 | 위치정보 수집·이용·제공사실 확인자료의 보유근거와 보유기간 |
| L3 | 개인위치정보의 파기 절차와 방법 |
| L4 | 개인위치정보의 제3자 제공에 관한 사항 |
| L5 | 법 제19조 제3항에 따른 통보(사후통보)에 관한 사항 |

| L7 | 위치정보관리책임자의 성명, 전화번호 등 연락처와 개인위치정보 보호 업무·고충 처리 부서의 명칭과 연락처 |

## 앱과 스토어 일관성

| # | 항목 | 확인 방법 |
|---|---|---|
| P17 | 앱이 요청하는 권한(위치, 카메라, 사진, 연락처, 건강, 광고추적)이 처리방침의 수집 항목에 모두 있다 | AndroidManifest, Info.plist, 권한 요청 코드와 대조 |
| P18 | iOS `PrivacyInfo.xcprivacy`의 수집 데이터 유형에 위치가 있다 (위치를 서버로 보낼 때) | 파일 확인. 사용자가 직접 운영하는 서버로만 가면 "판단 필요" |
| P19 | 스토어 개인정보 라벨(App Store 개인정보, Google Play 데이터 보안)과 처리방침이 모순되지 않는다 | 접근 가능하면 대조, 아니면 "확인 불가" |
| P20 | 처리방침에 적힌 위치 정밀도·보유기간이 코드와 같다 | `terms-checklist.md` D절과 같은 방식 |

## 판정 규칙

- 처리방침이 웹사이트만 다루고 앱 처리를 다루지 않으면, P 항목은 앱의 실제 처리 기준으로 채점한다 (앱 처리가 빠진 것 자체가 발견사항).
- 1층 항목 중 서비스에 해당하지 않는 것은 "해당없음"으로 두고 이유를 한 줄 적는다. 빈칸으로 두지 않는다.
- 처리방침이 웹 페이지면 원문을 받아 인용한다. 요약만 보고 "없음"으로 단정하지 않는다.
- 문서 간 충돌(예: 가입 화면은 마케팅 "선택", 마케팅 동의 문서는 "필수")은 별도 발견사항으로 적는다.
