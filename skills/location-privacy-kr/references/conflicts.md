# 규칙 충돌과 판정

원본 스킬 5개를 실제 앱(모바일 앱 1개, 오픈소스 위치 공유 앱 1개)에 돌려 보고, 서로 다른 결론을 내는 지점을 모아 판정했다. 판정 기준은 "트라이얼에서 실제로 문제를 잡은 규칙"이다.

| # | 충돌 | 판정 |
|---|---|---|
| 1 | **생성 대 점검.** 처리방침 생성 스킬은 인터뷰 후 새 문서를 만든다. 리뷰 스킬은 기존 문서를 평가한다. | 기본은 점검(audit). 새 문서는 fix 모드에서 점검 결과의 빈 곳만 채우는 초안으로 만든다. 기존 문서와 코드가 이미 있는 저장소에서 처음부터 다시 쓰면 실제 동작과 어긋난 문서가 또 생긴다. |
| 2 | **인터뷰 먼저 대 기본값으로 진행.** 생성 스킬은 관할 메뉴와 디자인 질문을 먼저 한다. 앱 스토어 스킬은 형식 질문에서 멈춘다. | 묻지 않는다. 대상 저장소, 문서 위치, 모드는 요청과 저장소에서 추정하고 보고서 맨 위에 적는다. 회사명·책임자처럼 추측하면 안 되는 값만 자리표시자로 둔다. |
| 3 | **GDPR 등급 대 한국법 등급.** 동의 흐름 스킬은 분석 동의 누락을 CRITICAL로, 약관 동의를 GDPR Art.6 법적 근거로 분류한다. | 심각도는 한국 법의 제재 종류로 정한다(형사 → 치명, 과태료 → 높음). GDPR 법적 근거 열은 쓰지 않는다. 다른 관할이 필요하면 별도 스킬을 쓰라고 안내한다. |
| 4 | **범위 축소 거부 대 요청 범위 존중.** PbD·동의 스킬은 "일부만 봐 달라"는 요청을 거부하고 전체를 본다. | 위치 데이터 지도는 항상 전체 저장소에서 만든다(위치가 어디로 새는지는 범위 밖에서 드러난다). 그 밖의 점검은 요청 범위를 따른다. 범위 때문에 못 본 것은 "확인 불가"로 적는다. |
| 5 | **확신 대 확인 불가.** 동의 스킬은 클라이언트 코드만 보고 집행 누락을 HIGH confidence로 단정한다. | 서버·운영 증빙이 필요한 항목은 "확인 불가"라는 별도 범주로 둔다. 통과도 위반도 아니다. 무엇을 보면 되는지를 같이 적는다. |
| 6 | **없는 것은 발견사항 대 해당없음.** 리뷰 스킬은 "누락은 신호"로 모든 행을 채점한다. 셀프호스팅 앱에서 계정·약관 행이 억지로 RED가 됐다. | 누락은 발견사항이다. 단, 서비스에 그 처리가 없으면 "해당없음: 이유"로 닫는다. 운영자가 없는 구조(사용자가 서버를 직접 운영)는 적용 판정 단계에서 먼저 가른다. |
| 7 | **확장자 좁히기 대 전체 검색.** 앱 스토어 스킬은 `.swift`만 검색해서 Objective-C 위치 코드를 놓쳤다. | 확장자를 제한하지 않고 저장소 전체를 `git grep`한다. 의존성 폴더만 뺀다. |
| 8 | **문서 요약 대 원문 인용.** 웹 요약 도구는 원문을 짧게 잘라 주고, 그 요약만으로 "항목 없음"이 나왔다. | 문서는 원문을 받아(`curl`) 인용한다. 원문을 못 받으면 해당 항목은 "확인 불가"다. 요약만 보고 누락으로 판정하지 않는다. |
| 9 | **법 개정 날짜·금액 단정 대 출처 표시.** 생성 스킬은 개정일과 과징금 비율을 사실로 적고, 이미 시행된 개정을 "예정"으로 썼다. | 금액·시행일은 출처와 "현행 조문 확인 필요"를 붙인다. 보고서에 점검일을 적는다. 기억으로 개인정보보호법 금액을 쓰지 않는다. |
| 10 | **기본 출력 "OK" 대 근거 있는 통과.** 생성 스킬의 출력 예시는 "법정 11개 항목: OK"로 시작한다. | 통과에도 근거(인용, 파일:줄)를 단다. 근거 없는 통과는 쓰지 않는다. |
| 11 | **OS 권한 = 동의 대 약관 동의 별도.** PbD·앱 스토어 스킬은 OS 권한 흐름만 보고 동의가 있다고 봤다. | OS 권한 허용은 위치정보법상 동의가 아니다. 약관 명시 후 별도 동의와 서버 상태를 따로 확인한다. OS 권한 해제도 동의 철회로 보지 않는다. |
| 12 | **보안 체크리스트 기계 적용 대 실제 저장 여부.** PbD 스킬은 저장하지 않는 좌표에도 "저장 시 암호화 없음"을 냈다. | 저장 관련 항목은 위치 데이터 지도에서 저장이 확인된 데이터에만 적용한다. 저장하지 않으면 그 사실과 증빙 후보(삭제 코드)를 적는다. |
| 13 | **무거운 보고서 대 실행할 수 있는 보고서.** 동의 스킬은 표 6개, PbD는 산출물 7개를 요구했고 대부분 비었다. | 요약(5분) + 발견사항 표 + 확인 불가 목록이 기본이다. 항목별 판정은 부록. 빈 표는 만들지 않는다. |
| 14 | **수정 전 승인 대 자율 수정.** 쿠키 스킬은 바꾸기 전에 계획에 동의를 받으라고 한다. | fix 모드를 요청받았으면 저장소 안의 코드·문서 파일 수정은 바로 한다. 외부에 나가는 일(웹 문서 게시, 배포, 신고 제출, 운영 DB 변경)은 하지 않고 안내만 한다. |
| 15 | **행동 측정 대 코드 읽기.** 쿠키 스킬은 실제 브라우저 스캔만 증거로 인정한다. 코드 리뷰 스킬은 코드만 본다. | 코드가 기본 증거다. 실행해 볼 수 있으면(시뮬레이터, 프록시) 실행 결과를 우선 증거로 쓰고, 못 했으면 "정적 분석 기준"이라고 적는다. |
| 16 | **마케팅 문구 대 중립.** 한 원본 스킬은 호출 때마다 커뮤니티 홍보 문구를 그대로 출력하게 한다. | 홍보·외부 링크 출력 없음. 출력은 점검 결과와 수정 사항만. |
| 17 | **운영 주체 미정 대 해당없음.** 셀프호스팅 앱은 배포자가 위치를 받지 않을 수 있는데, 사용자는 "출시한다고 가정"하고 점검을 원했다. | 점수는 매기고 `조건부(전제: …)`를 붙인다. 전제가 거짓으로 확정될 때만 해당없음으로 닫는다. |
